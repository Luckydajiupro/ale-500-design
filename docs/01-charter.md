# 项目章程

这份文件回答四件事：为什么做这个项目、做什么、不做什么、最后交什么。读完这一份不需要再读别的文件就能说清项目边界。

## 项目是干什么的

为 ALE 评测集生产 500 条原创的专业工作任务，并通过合作方验收。

ALE 全称 Agents' Last Exam，官方对自己的定义是覆盖面最广的 Agent 评测基准，衡量的是长流程、有经济价值、结果可验证的任务，覆盖 13 个行业簇下的 55 个子域，职业分类参考 O*NET / SOC 2018，由 Berkeley RDI 联合主导，由数百名行业专家供稿。这段定义来自官方仓库 `inputs/frozen/01_agents-last-exam/README.md` 第 30 至 35 行。

三个限定词是重点。长流程指任务要跨很多步骤，不是一问一答。有经济价值指任务本身是真实岗位上会做的工作。结果可验证指对错能被确定性判分，而不是靠感觉打分。

因此一条 ALE 任务至少包含：任务说明、原始资料、输入文件、执行环境、可执行的多步操作、预期交付物、判定成功的方法。这七样缺一样，任务就只能算描述，不能算任务。

## 500 条怎么算

500 指最终通过全部验收的有效新任务数量。

一条任务要依次通过四道门才算数：

1. 内容审核。专业上真实、结构完整、资料可授权。
2. 工程转换。能按目标版本转成 ALE 任务包。
3. 运行验证。在目标环境里能启动、能跑完、能被判分。
4. 合作方交付验收。合作方抽验通过。

官方已有的 122 条任务不计入 500。它们只用于研究能力边界、格式、难度分布和评测方式。这一点是 Phase 0 的冻结结论，出处是 `stages/s0-baseline/00_project_brief.md`。

专家提交了多少条、平台生成了多少条、工程转换了多少条，都不算 500。只有第 4 道门过了才计数。

## 做什么，不做什么

做的是 ALE 兼容的原创扩展任务集。每条新任务有独立的业务场景、独立的资料、独立的数据集和独立的任务文本，在专业工作流、能力要求、复杂度和可验证性上与官方目标能力对齐，能按合作方冻结的 ALE / Harbor 版本转换、运行和评测。

不做以下六件事。

第一，不复制官方任务的正文、隐藏评分规则或受限资产。官方任务只做参考。

第二，不让专家直接写底层运行代码。专家不碰 Docker、不碰验证器、不碰任务目录结构。

第三，不在没有验证的情况下承诺 500 条全部覆盖 Windows、GPU 或专有软件。这三类环境目前都还没有跑通记录。

第四，不用研究阶段的数字直接推导正式配额和专家人数。研究候选数、任务族数、能力组数都是观察结果，不是分配方案。

第五，不在试点之前一次性冻结所有人工审核比例和产能参数。

第六，不把专家生产平台做成最终的 ALE 运行和评测平台。平台只负责把专家知识整理成工程能接手的形式。

## 最后交什么

交付物是一整套可复核的东西，不只是一个数量。

任务包、任务所需资产和脱敏说明、任务与资产与评测与版本的清单、文件哈希和来源记录、运行验证结果、评测结果和质量报告、已知问题和限制、合作方可以照着复现的交付说明。

清单和哈希是交付的一部分，不是附属品。没有它们，合作方无法确认收到的就是验收过的那一版。

## 六件真正难的事

项目难的地方不是写 500 段任务描述，而是下面六件事同时成立。任何一件崩了，数量到了也交不出去。

第一，专家能不能拿出真实且可授权的工作资料。招到人不等于拿得到资料，资料能用不等于能公开。这是整条链上最花钱也最难买的一环。

第二，专家脑子里的隐性经验能不能被结构化。老手做一件事靠的是判断，判断说不清就写不成任务契约。

第三，任务能不能被另一个人照着复现。只有原作者做得出来的任务，工程和评审都无法验证。

第四，工程能不能不反复追问专家就完成格式转换。每问一次，成本就翻一倍，节奏就断一次。

第五，Windows、GPU、图形界面、外部服务和专有工具是不是真的能跑。官方 122 条里 36 条是 Windows，3 条需要 GPU，13 条依赖外部服务，这些在 Phase 0 全部没有实际运行记录。

第六，评测是不是真的在考任务目标。环境报错、超时、评分器漏洞都会让分数失真，跑出分数不等于跑对了。

## 两条链路必须分开

官方参考研究链和专家新任务生产链是两件事，不能混。

官方那 122 条只走研究链，产出的是能力基线、格式约束和环境认知。专家新生产的任务走生产链，产出的是交付物。专家写的规范任务源是新的生产物，不是官方任务的改写版。

两条链分开的好处是，官方版本升级不会逼专家重做，专家写得慢也不会卡住研究。

## 关键约束

专家负责专业内容、原始资料、预期产物和成功标准。工程负责格式、环境、验证器和评测。平台负责字段、权限、状态、文件、审计和交接快照。项目负责人负责范围、配额、资源、门禁和批次放行。

任何一方越权替另一方作决定，都会在生产阶段产生返工。专家不能决定验证器怎么写，工程不能改专家的业务内容，平台不能替专家判断专业正确性。

500 条正式配额、Windows 与 GPU 是否进首期、预算与排期已经裁决。目标版本冻结仍是合作方和项目负责人的待定项，决定权在项目负责人。
