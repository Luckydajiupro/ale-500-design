## 我做的决定

| 编号 | 决定 | 理由 |
| --- | --- | --- |
| D1 | 十一个状态：`draft` 到 `ingested`，旁路 `returned` 与 `void`；删除 `handed_off` | 组包、校验、入库是平台的新终点；交接是动作，不是状态 |
| D2 | 不引入工作流引擎，用固定状态机加代码守卫 | 14 个 domain_code 各一套流程会让回归成本失控 |
| D3 | 交接物是 ALE-data 包加 `package_manifest.json`，工程不连平台 | 包是唯一边界；平台停机不影响工程转换 |
| D4 | 类目差异只进配置：必填项、资产上限、评审角色、风险规则 | 新增类目不改状态机，30 分钟上线 |
| D5 | 单机 Docker Compose，不上集群 | 500 条、峰值 44 人在岗，集群是过度设计 |
| D6 | 许可、隐私、IRB 是阻断字段，不是提示字段 | 事后补许可比事前填贵一个量级 |
| D7 | 风险分层默认规则写进配置，负责人可改阈值 | docs/03 未冻结阈值，平台不替它冻结 |
| D8 | 试点是商业会计、神经影像、建筑节能，共 3 条；11-18 签约，12-30 收口 | 试点是人工标注到平台辅助标注的迁移探索，不是 Harbor 四段验收；法律 8 条走供应方导入，不占试点位 |
| D9 | 配额建议给 `agriculture_env` 补 16 条 | 08 草案漏了这个域，不能按 12 类做覆盖；与专家供给 v1 对齐 |
| D10 | 试点 500 GiB，前 100 条升 1 TiB，按 70% 水位升 2 TiB | 中档资产 live 280 GiB，热占用 316 GiB，512 GiB 到 62%；为导出包与快照留量仍升 1 TiB，低档 135 GiB 放得下 |
| D11 | 库内存规范化 JSON，平台自动生成 ALE-data 包；Harbor 只在工程侧转换 | Harbor 是运行格式，字段随引擎变；平台核心 Schema 不出现 `harbor_*` |
| D12 | 供应方包走导入 → 校验 → 隔离区 → 人工确认 → 入库；A/B 共用 `entrypoints` 与 `PACKAGE.json` | 官方 ale-data 没有 license/provenance，边车补字段又不改数据布局；隔离区让坏包不污染任务表 |
| D13 | 评审不单设岗位，四批每批 22 名核心加 4 名后备，同批人既生产也评审 | 评审负荷 1,175 小时，摊到 22 人是每人每周约 2 小时；另招一批专职评审养不起也用不满 |
| D14 | 派单用固定五步规则排序，不做模型打分；算法版本入库，旧派单不回溯 | 规则可解释、可重放，出了争议能复盘；模型打分在试点期拿不到足够样本 |
| D15 | 评审 SLA 5 个工作日，第 3 天提醒，第 5 天自动改派；每批首周 3 条盲评，10% 双评，错误率 20% 移出 | 22 人兼职评审，没有硬时限就会在批次末尾堆积，改派比催人更可预期 |
| D16 | W1 8.5 周（12-01 到 01-31，已批准），W2 到 W4 各 6.5 周，W2 到 W4 窗口不变，04-30 交付 | 30 条 12-25 完成，90 条 01-01 到 01-31 有 4.3 周；旧 01-15 窗口 101% 负荷，不可执行 |
| D17 | 平台终点改到 `ingested`，新增 `packaged`、`package_validated`；入库记录独立状态 | 生产完成与最终验收分开，避免把入库当计入 500 |
| D18 | 平台自动组包、L1 到 L5 校验、幂等入库；Harbor、镜像、运行、判分移出平台 | 新基线要求平台交付完整 ALE-data，不把运行格式当库内格式 |
| D19 | Agent 五能力只写建议，专家逐字段确认；单任务 120 元、试点 60 元；p95 8s/60s/90s | 自动采纳会让专业判断失控；成本和延迟不设上限会拖垮批次 |
| D20 | 包契约用 `entrypoints` 声明角色路径，`contract.kind` 五种，`license` 三态，`files[].role` | 官方 122 条至少三种互不兼容形态，固定文件名会误拒 120 条 |
| D21 | M1a 拆 M1a-Core（11-30，六项）与 M1a+（12-15，两项）；M1b（12-22，四项）；M2 拆 M2-C（12-31）与 M2-Full（2027-01-31） | 30 条可以先开工，组包等 M1b；不让平台开发卡死生产 |
| D22 | 首批 22 条 100% 双评，W1 评审约 235 小时；30 条 12-25 目标、12-31 收口 | 首批质量优先；235 小时低于 294 小时上限，不需要加评审岗 |

1. `stages/s0-baseline/08_coverage_matrix_draft.csv` 漏了 `agriculture_env`，12 类合计 500。本方案显式补 16 条并保持总数 500。这是最需要拍板的一条。
2. `work/platform-p1-design-v0.md` 是八状态，本方案是十一状态。v0 只作历史；以 `06` 第 3 节为准。
3. `work/recruitment-plan-v0.md` 的首批是法律、神经影像、建筑节能；本方案是商业会计、神经影像、建筑节能，法律 8 条走供应方导入。v0 的绝对日期作废。

7. `docs/` 已补 ALE-data 生产完成与验收完成两计数器、阶段 2 试点出口、阶段 3 M1a/M1b/M2。本方案是详细设计，不重复 `docs/02` 的阶段判据；冲突时以 `docs/02` 为准，平台能力细节以 `06` 为准。
